# Current Status

Last updated: 2026-10-05

`media-library-desktop`는 Electron + React + SQLite 기반의 개인용 미디어 라이브러리 앱입니다. PDF, ZIP(CBZ 포함), 비디오 파일을 등록하고, 썸네일, 진행률, 태그, 리뷰, 다국어 UI를 함께 관리하는 방향으로 구현되어 있습니다.

## 현재 구현 상태

- 순서 8의 복수 플레이리스트 지원을 완료했습니다. 프로필마다 목록을 생성·이름 변경·삭제·선택하며, 라이브러리 패널의 선택 필드에 목록 이름과 항목 수를 함께 표시합니다. 그 아래 왼쪽에 생성·이름 변경·초기화 SVG 아이콘 버튼을, 오른쪽 끝에 빨간 아이콘의 삭제 버튼을 배치합니다. 아이콘은 더하기·빈 실선 사각형+연필·빈 점선 사각형·X이며 버튼 크기는 툴바와 같고 다국어 title·ARIA 이름을 유지합니다. 헤더 padding은 `10px 10px 10px 28px`이며 왼쪽 패널에서는 좌우를 반대로 적용합니다.
- 기존 `Default`의 id·항목·순서는 유지하며 일반 목록처럼 이름 변경과 삭제를 허용합니다. 마지막 목록은 삭제할 수 없고, 프로필에 목록이 전혀 없을 때만 `Default`를 생성합니다.
- 마지막 선택은 프로필 설정 `playlist.activeId`에 저장합니다. 삭제되거나 다른 프로필의 id이면 현재 프로필의 가장 오래된 목록으로 보정합니다. 새 목록 생성 시 해당 목록을 선택합니다.
- 추가 버튼과 drag and drop은 선택한 목록을 사용합니다. 라이브러리 카드 메뉴의 `리스트에 추가` 하위 메뉴에 모든 목록을 표시합니다. 파일이 등록된 목록마다 체크 아이콘을 표시하고 현재 선택 목록은 메뉴 오른쪽의 `(현재)` 문구로 구분합니다. 메뉴를 열 때 등록 여부를 다시 조회합니다. 목록이 하나여도 하위 메뉴를 사용하며, 추가 대상 선택은 현재 목록을 변경하지 않습니다. 항목 추가는 패널의 접힘 상태를 유지합니다. 패널이 이미 펼쳐져 있으면 현재 선택된 플레이리스트에 포커스를 둡니다. 같은 파일은 여러 목록에 등록할 수 있으며 같은 목록의 버튼 중복 추가는 순서를 유지합니다. 위치를 지정한 drop은 기존 항목을 해당 위치로 이동합니다.
- 뷰어는 진입 당시 목록 id를 유지합니다. PDF·ZIP·동영상 간 이동, 플레이리스트 항목 클릭, 이전·다음과 자동 이어보기에서도 같은 목록을 사용합니다. 목록 전환은 라이브러리에서만 하며 현재 파일이 진입 목록에 없으면 이전·다음·자동 이어보기를 실행하지 않습니다.
- 삭제·초기화는 확인 Modal을 거치며 등록 관계만 제거합니다. 라이브러리 항목과 실제 파일은 유지합니다. `.db` 가져오기는 여러 목록을 기존 방식으로 이관하며 선택 목록 id를 대상 DB의 id에 매핑합니다. 복제·내보내기는 구현 범위와 후속 후보에서 제외합니다.
- 단위·통합 테스트 79개(플레이리스트 통합 11개 포함), 신규 Electron E2E 3개, main/preload·renderer 타입 검사와 빌드를 통과했습니다. 우클릭 메뉴의 복수 등록 체크·현재 표시·선택 전환·중복 추가 방지는 관련 E2E 1개를 갱신해 재검증했습니다. 기존 E2E 전체 실행은 20개 중 16개 통과·4개 실패였으며, 실패는 태그 관리 테스트의 데이터 관리 탭 진입 누락 3건과 언어 선택 버튼의 모호한 선택자 1건입니다. 전체 테스트 안정화는 별도 후속 작업으로 남깁니다.

- 순서 7의 PDF·ZIP 스크롤 보기와 항목별 표시 방식 저장을 완료했습니다. 툴바·컨텍스트 메뉴에서 한 페이지, 스크롤, 두 페이지 좌→우/우→좌를 선택합니다. `1`은 한 페이지↔스크롤, `2`는 두 페이지 방향 전환이며 한 페이지·두 페이지 보기의 기존 페이지 단축키와 공통 플레이리스트 단축키를 유지합니다.
- 표시 방식은 nullable `items.bookViewMode`에 저장합니다. 저장값이 없거나 유효하지 않으면 한 페이지로 열며 과거 `pdf.viewMode`/`cbz.viewMode` 프로필 설정은 읽지 않습니다. 항목 이동·복사와 과거 DB 가져오기에서도 유효한 값을 유지합니다.
- 스크롤 보기는 이미지 비율에 따른 실제 높이로 연속 배치하고 페이지 간격과 최소 화면 높이 여백을 제거했습니다. 100%에서는 컨테이너와 1000px 중 작은 폭을 사용하며, 스크롤 전용 축소·배율 초기화·확대 버튼으로 50~300%를 25%씩 조절합니다. 확대 결과가 창보다 넓으면 가로 스크롤할 수 있습니다.
- 확대·축소 툴바 버튼은 흰색으로 표시합니다. 마우스를 움직이면 나타나는 상단 툴바의 `− / 배율 / +`와 스크롤 보기의 우클릭 메뉴에서 조절합니다. 우클릭 메뉴는 페이지 모드 바로 다음의 `확대/축소` 하위 메뉴에 확대·배율 초기화·축소 순으로 묶습니다. `+`/`-`는 25% 확대/축소, `0`은 100% 초기화이며 일반 키보드와 숫자 키패드를 지원합니다. 배율 버튼이나 `배율 초기화 (100%)` 메뉴도 100%로 되돌립니다.
- 툴바 배율 버튼과 컨텍스트 메뉴의 `확대/축소` 그룹은 스크롤 보기에서만 표시합니다.
- 스크롤 컨텍스트 메뉴의 위로·아래로 스크롤 앞에는 방향 아이콘을 표시하고 단축키는 `zxcvbnm,./ ↑`·`Space ↓`처럼 방향키를 가장 오른쪽에 공백 한 칸으로 구분해 배치합니다.
- 스크롤 모드의 위 방향키와 `zxcvbnm,./`는 위로, 아래 방향키와 `Space`는 아래로 읽기 영역 높이의 50%만큼 240ms 애니메이션으로 이동합니다. 좌·우 방향키는 이전·다음 페이지로 이동합니다. 컨텍스트 메뉴에는 위로 스크롤·아래로 스크롤·이전 페이지·다음 페이지를 순서대로 표시하며 동작에 맞는 단축키를 안내합니다. 페이지 변경 시 위치를 다시 대입하지 않고, 높이·배율 변경 시 같은 페이지 안의 비율을 유지해 경계에서 애니메이션이 끊기던 문제를 수정했습니다.
- `items.bookScrollZoom`과 `items.bookScrollOffset`에 배율과 페이지 위쪽에서의 0~1 위치 비율을 저장합니다. 화면 위쪽 페이지를 현재 페이지·진행률·썸네일 기준으로 사용하며, 재진입과 창 크기 변경 후에도 페이지 내 비율을 복원합니다. 위치는 180ms debounce로 저장하며 뷰어 종료·파일 전환·모드 변경 시 대기 저장을 반영합니다. 값이 없는 항목은 100%와 페이지 시작으로 표시합니다.
- 스크롤은 읽기 화면과 주변 화면의 요소만 렌더링합니다. ZIP은 화면에 걸치는 페이지 수(최소 2페이지)를 기준으로 현재·다음·이전 범위를 보관하고 기존 128MiB 추정 예산을 유지합니다. 한 화면에 짧은 페이지가 여러 개 보이면 보관 개수도 증가합니다. 이미지 크기 정보는 URL 해제 후에도 세션 동안 유지하며 PDF는 범위 밖 canvas와 파일 전환·종료 시 문서/작업을 해제합니다.
- 단위·통합 테스트 68개, 관련 Electron E2E 3개, main/preload·renderer 타입 검사와 빌드를 통과했습니다. E2E는 PDF·ZIP의 긴 페이지 경계 애니메이션, 간격 0, 확대 중 위치 유지, 즉시 종료·다른 창 크기·앱 재실행에서 배율/위치 복원과 기존 뷰어·캐시 동작을 검증했습니다.

- 순서 6의 ZIP 페이지 이동 성능 개선을 완료했습니다. 파일을 한 번 읽고 연 ZIP 세션을 재사용하며 바이너리 IPC와 Blob URL로 페이지를 표시합니다. 현재 화면과 앞뒤 한 화면(한 페이지 보기 최대 3페이지, 두 페이지 보기 최대 6페이지)을 보관하고 이미지 추정 예산 128MiB를 적용합니다. 현재 화면은 예산보다 커도 유지하며 ZIP 원본과 로딩 중 메모리는 별도입니다.
- ZIP 뷰어 종료·파일 전환·reload 시 세션과 이미지 URL을 해제합니다. 빠른 이동 중 오래된 응답을 폐기하고 저장된 페이지 범위를 보정하며 손상·빈 ZIP 및 이미지 decode 실패를 표시합니다.
- 약 118.71MiB·96페이지 합성 ZIP에서 파일 처리 요청 평균은 기존 131.22ms에서 6.96ms로 줄었습니다. 별도 Electron 측정은 첫 표시 약 227ms, 미리 읽은 페이지 이동 약 1~2ms, 먼 페이지 이동 약 77ms였습니다. 사용자 파일이나 cold disk의 성능을 보장하는 수치는 아닙니다. 상세 조건은 `zip-performance.md`에 기록했습니다.
- ZIP 세션·보관 예산·응답 경합 테스트 11개를 추가했습니다. 전체 단위·통합 테스트 67개, 관련 Electron E2E 4개, 타입 검사와 빌드를 통과했습니다. 스크롤 보기와 항목별 표시 방식 저장은 후속 순서 7에서 완료했습니다.

- 마지막 창의 일반 크기·좌표, 표시 모니터 id·작업 영역과 최대화 상태를 포터블 userData의 `window-state.json`에 저장하고 다음 실행에 복원합니다. 프로필과 별도로 관리하며, 전체화면·최소화 상태는 다시 실행하지 않습니다.
- 이전 모니터가 없으면 기본 모니터 가운데에 표시하고, 작업 영역이 바뀌면 크기와 좌표를 현재 화면 안으로 보정합니다. 손상된 저장값은 기본 1280×800 창으로 fallback합니다.
- PDF·ZIP·동영상 뷰어는 커서가 창 안에 있어도 2.4초 동안 조작이 없으면 툴바·플레이리스트 패널·커서를 숨깁니다. 마우스 이동·클릭·키 입력·창 포커스 복귀 시 다시 표시하고, 컨텍스트 메뉴가 열린 동안은 유지합니다. 동영상 일시정지와 반복 재생에도 같은 기준을 적용합니다.
- 숨긴 툴바는 `inert`로 포커스와 클릭을 차단합니다. 동영상 seek bar는 16px 높이의 조작 영역 안에 전체 폭 막대를 배치합니다. 막대는 기본 6px이며 마우스 호버 시에만 160ms transition으로 12px까지 두꺼워집니다. 배경·hover 구간·현재 재생 구간 순서로 표시하고, 두 구간이 겹치는 부분을 반투명 흰색으로 밝게 표시합니다. 현재 재생 시점 이전으로 hover해도 위치를 구분할 수 있으며, hover 예상 시각도 표시합니다. 볼륨 조절 바도 높이 16px 조작 영역과 기본 4px·호버 시 12px 막대를 사용합니다. 트랙만 160ms transition으로 확장하고 thumb는 중앙에 고정해 움직이지 않습니다.
- 창 재실행·최대화·전체화면 종료 후 복원, PDF·ZIP 자동 숨김과 복귀, 실제 WebM 재생·일시정지·반복 재생·seek hover와 동시 진행 표시를 Electron E2E 3개로 검증했습니다. 단위·통합 테스트 56개, main/preload·renderer 타입 검사와 빌드도 통과했습니다.

- 설정 팝업을 `기본 설정`(표시 설정, 파일 수정일 변경 규칙), `데이터 관리`(태그명 변경·병합, 폴더 경로 일괄 변경, HDT 가져오기), `프로필 관리`(프로필명 변경, 과거 데이터 불러오기) 순의 탭으로 분류했습니다. 폭은 720px, 최대 높이는 860px이며 팝업을 열 때마다 `기본 설정` 탭을 선택합니다. `scrollbar-gutter: stable both-edges`로 좌우에 같은 공간을 확보해 스크롤 유무와 관계없이 설정 그룹을 가운데에 배치합니다.

- 설정 팝업의 데이터 관리 탭 첫 항목으로 `태그명 변경·병합`을 제공합니다. 현재 프로필의 사용 중인 태그를 이름·내부 id·연결 건수로 선택합니다.
- 변경 전·후 태그는 레이블과 중간 구분선 없이 placeholder로 구분한 연속 입력입니다. 공용 `TagSearchInput`으로 기존 태그를 검색하고, 변경 후에는 새 이름도 직접 입력합니다. 이 섹션에서는 태그 id 표시와 id 검색을 활성화합니다.
- 태그명 변경·병합의 두 입력은 후보 선택 후 이름을 유지하고 목록을 닫습니다. 입력 재클릭·수정·방향키로 다시 열고, 포커스가 입력 그룹 밖으로 나가면 닫습니다. 입력 내부 우측의 빨간 원형 X 버튼은 입력값과 해당 선택을 비우며, 빈 입력에서는 숨깁니다.
- 공용 태그 검색은 기본 최대 20건이며 출력 건수와 데이터 수 정렬 방향을 지정할 수 있습니다. 태그명 변경·병합은 최대 50건, 변경 전 오름차순·변경 후 내림차순을 사용합니다. 변경 후부터 입력할 수 있으며 실행에는 유효한 변경 전 태그와 변경 후 이름이 모두 필요합니다.
- 태그 60개를 사용하는 Electron E2E로 변경 전·후 모두 검색어 유무와 관계없이 최대 50건을 표시함을 확인했습니다. 검색 팝업은 기본 20건을 유지합니다. 검색어 `가`의 20건 표시는 마지막 사용 프로필의 사용 중인 태그 588개 중 실제 포함 검색 일치가 20개여서 발생한 것으로 확인했습니다.

## 현재 강점

- 단일 앱으로 필요한 기능이 꽤 많이 묶여 있습니다.
- 메인/렌더러/프리로드 경계가 비교적 명확합니다.
- 포터블 실행을 고려한 데이터 경로 처리가 들어가 있으며, 과거 DB는 설정 팝업에서 명시적으로 가져옵니다.
- startup 상태 이벤트를 통해 느린 초기 실행 상황을 사용자에게 설명할 수 있습니다.
- 기능 추가 흔적이 상태 문서, 결정 기록, backlog로 남아 있어 다음 작업을 이어가기 쉽습니다.

## 현재 한계와 리스크

- `LibraryPage.tsx`에서 툴바, 카드, 목록, 주요 모달 렌더링과 파일 추가/HDT/설정 흐름 hook이 분리되었습니다.
- 공용 `Modal`에 focus trap과 dialog ARIA 속성을 추가했으며, 중첩 Modal에서는 최상단 Modal만 `Escape`/`Tab` 키 이벤트를 처리합니다.
- 라이브러리 카드 컨텍스트 메뉴에서 상세 정보, 뷰어 열기, 외부에서 열기, 출처 URL 열기, 파일 위치 열기를 사용할 수 있습니다.
- `items:getAll` 목록 응답에 `sourceUrl`을 포함해 컨텍스트 메뉴와 상세 팝업의 출처 URL 동작을 맞췄습니다.
- `LibraryPage.tsx`의 주요 렌더링, 검색/필터, 썸네일, metadata fill 흐름은 전용 컴포넌트와 hook으로 분리되었습니다.
- `items` IPC는 진입점과 core/relink/imports/metadata 세부 모듈로 분리되었습니다. renderer/preload의 `api.items.*` 호출명은 유지합니다.
- 뷰어 화면의 `ESC`, `Backspace`, 라이브러리/상세 팝업 포커스 이동, 검색 툴바/페이지네이션/설정 팝업 `title` 동작은 확인 완료했습니다.
- renderer 코드의 `alert()`, `confirm()`, `prompt()` 호출은 제거했습니다.
- Electron E2E는 프로필 선택, 신규 생성, 다음 실행 자동 진입과 항목 복사·중복 이동 차단을 검증합니다.
- SQLite 통합 테스트는 항목 이동·복사, 프로필 삭제 이관의 중복 처리, 태그·리뷰·플레이리스트 연결 정리를 검증합니다.
- `npm test`는 Electron의 Node 실행 모드로 Vitest를 구동해 `better-sqlite3` 통합 테스트를 실행합니다.
- 그 밖의 파일 추가, relink, HDT, 키보드 조작, 플레이리스트 흐름은 자동 검증이 더 필요합니다.
- 개선 전 병목 후보는 DB 초기화보다 창 생성과 renderer 로드 구간이었습니다.
- 뷰어 route lazy loading 적용 후 production renderer 초기 JS는 약 `1,705.13 kB`에서 약 `847.29 kB`로 줄었습니다.
- 플레이리스트 자동 다음 항목 실행은 PDF, CBZ, 비디오 뷰어에 연결되어 있습니다.
