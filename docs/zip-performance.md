# ZIP 뷰어 성능

측정일: 2026-10-05

## 적용 범위

- 순서 6의 기존 한 페이지·두 페이지 보기 성능을 개선했습니다.
- ZIP 파일 읽기와 JSZip 열기는 뷰어 세션마다 한 번 수행합니다. 현재 파일의 압축 데이터는 세션 동안 유지하고 압축 해제된 이미지는 main에 누적하지 않습니다.
- 페이지는 바이너리 IPC로 전달하고 renderer에서 Blob URL 생성과 이미지 decode 후 표시합니다.
- 스크롤 보기와 항목별 표시 방식 저장은 순서 7에서 별도 진행합니다.

## 주변 보관과 메모리

- 한 페이지 보기의 현재 페이지가 5라면 5, 6, 4 순으로 읽고 최대 3페이지를 보관합니다.
- 두 페이지 보기의 현재 화면이 5~6이라면 5~6, 7~8, 3~4 순으로 읽고 최대 6페이지를 보관합니다. 오른쪽→왼쪽 보기에도 같은 페이지 범위를 사용합니다.
- 파일 양 끝에서는 존재하는 페이지만 읽습니다. 빠른 이동으로 범위가 바뀌면 진행 중 페이지 한 개의 완료를 기다린 뒤 최신 화면을 우선하고, 범위 밖 결과는 해제합니다.
- 이미지 예산은 128MiB이며 파일 바이트와 정적 RGBA 크기 `width × height × 4`를 합산한 추정치입니다. 현재 화면을 제외한 주변 이미지를 먼저 제거합니다. 현재 화면이 예산을 초과하면 그대로 표시하고 추가 미리 읽기를 중단합니다.
- ZIP 원본, 일시적인 IPC 복사·압축 해제·decode, 브라우저 내부 메모리는 이미지 예산과 별도입니다. JSZip은 현재 ZIP의 압축 데이터를 메모리에 유지하므로 아주 큰 ZIP을 처음 열 때의 메모리와 시간은 파일 크기의 영향을 받습니다.
- 파일 전환·뷰어 종료·창 종료·renderer crash·전체 페이지 reload 시 해제합니다. 디스크 캐시는 사용하지 않으며 외부에서 수정된 ZIP은 다시 열어 읽습니다.

## 파일 처리 측정

`node scripts/benchmark-cbz.cjs --optimized`로 합성 fixture를 생성하고 동일한 ZIP에서 기존 경로와 새 서비스를 비교했습니다. fixture는 `.data/cbz-benchmark/`에 저장하며 Git에서 제외합니다. 이는 측정용 파일이며 뷰어 디스크 캐시가 아닙니다.

- 크기: 118.71MiB, 96페이지
- 이미지: 1024×1536 무작위 RGB를 JPEG quality 90으로 생성하고 같은 이미지를 96개의 독립 ZIP entry로 저장
- ZIP 압축: DEFLATE level 1
- 요청 index: 0, 1, 2, 3, 4, 5, 80, 79
- 기존 경로: 요청마다 동기 파일 읽기·JSZip 열기·목록 정렬·압축 해제·base64 변환
- 새 경로: 비동기 파일 읽기와 JSZip 열기 한 번, 이후 압축 해제와 바이너리 반환

| 구간 | 측정값 |
|---|---:|
| 기존 페이지 요청 평균 | 131.22ms |
| 기존 파일 읽기 평균 | 29.79ms |
| 기존 ZIP 열기·목록 정렬 평균 | 92.08ms |
| 기존 압축 해제·base64 평균 | 9.35ms |
| 새 ZIP 열기 한 번 | 131.51ms |
| 새 페이지 요청 평균 | 6.96ms |
| 새 ZIP 열기와 첫 페이지 요청 합계 | 139.29ms |

페이지 요청 평균은 약 95% 줄었습니다. 이 비교는 IPC·이미지 decode·화면 표시를 포함하지 않습니다. 새 ZIP 열기 비용은 별도로 표시했으며 OS 파일 캐시를 비우지 않았습니다.

## Electron 화면 측정

`npx playwright test -g "measures first display"`는 임시 DB와 별도의 약 118.72MiB 합성 ZIP을 사용합니다. 페이지 81에서 시작해 미리 읽은 82, 이전 81, 먼 페이지 1로 이동하며 두 페이지 보기와 종료 해제도 확인합니다.

| 구간 | 측정값 |
|---|---:|
| 뷰어 진입부터 첫 이미지 표시 준비와 다음 animation frame | 약 227ms |
| 미리 읽은 다음 페이지 이동 | 약 1.7ms |
| 미리 읽은 이전 페이지 이동 | 약 1.4ms |
| 미리 읽지 않은 먼 페이지 이동 | 약 77ms |
| 이미지 decode 평균 | 약 17.6ms |

위 값은 해당 개발 환경의 단일 실행 결과입니다. 실제 사용자 파일, cold disk, 더 큰 이미지와 여러 GiB ZIP의 수치로 일반화하지 않습니다. 미리 읽지 못한 페이지는 압축 해제·IPC·decode 시간이 필요합니다.

## 검증

- ZIP 세션·범위 검증·동일 요청 합류·종료·reload·오류 회복과 이미지 예산·빠른 이동·늦은 응답 해제 테스트 11개 추가
- 전체 단위·통합 테스트 67개 통과
- 관련 Electron E2E 4개 통과: 주변 URL 수와 재사용, 두 페이지 방향, 빠른 이동, 플레이리스트 파일 전환·종료, 손상·빈 ZIP, 큰 ZIP 측정, 기존 콘텐츠 분류·뷰어 연결
- main/preload·renderer 타입 검사와 production 빌드 통과
