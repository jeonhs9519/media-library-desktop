# Decisions

프로젝트 운영과 문서화 방식에 영향을 주는 결정을 기록합니다.

날짜별 결정은 당시 기준으로 보존합니다. 이후 결정이 이전 범위를 대체할 수 있으며 현재 구현은 [Current Status](current-status.md)와 [Architecture](architecture.md)를 기준으로 확인합니다.

## 2026-10-06

### 과거 DB 가져오기의 프로필 복원

- 원본 사용자 프로필은 이름이 같은 현재 프로필에 연결하고 없으면 생성합니다. 원본 ID를 현재 ID로 복사하지 않습니다.
- GUEST는 GUEST로 연결하고, 프로필 정보가 없는 행과 UNASSIGNED는 현재 프로필에 등록합니다. 알 수 없는 사용자 프로필 참조를 현재 프로필로 임의 전환하지 않습니다.
- 같은 프로필의 중복 항목·설정은 기존 데이터를 유지합니다. 원본에 없는 항목 필드는 현재 기본값 또는 NULL을 사용하며, 기존 빈 문자열은 보존합니다.
- 프로필·항목·태그·리뷰·플레이리스트·설정 복원과 사용하지 않는 가져온 태그 정리를 하나의 transaction으로 묶습니다.
- 이전 가져오기로 이미 GUEST에 등록된 항목을 자동 삭제하거나 이동하지 않습니다. 다시 가져올 때 원본 프로필 소속의 데이터를 별도로 복원합니다.

## 2026-10-05

### 0.2.0 릴리즈

- `0.1.0` 이후 기능 추가·성능 개선·테스트와 구조·문서 안정화의 누적 변경을 사용자 지정 버전 `0.2.0`으로 묶습니다. 버전별 릴리즈 노트와 현재 상태 문서를 함께 갱신하고 기존 태그 기반 Windows ZIP 배포 경로를 사용합니다.

### 문서 안정화와 완료 범위

- 현재 상태는 기능별 구현 사실과 최신 검증으로 정리하고 작업 경과·과거 검증 건수는 Changelog와 측정 문서에 남깁니다. 최신 테스트 건수는 Current Status에서 관리합니다.
- 기존 Electron 기능 개선·테스트 보강·구조 안정화·문서 안정화는 완료했습니다. Tauri 준비는 별도 요청으로 착수하며 플레이리스트 복제·내보내기는 범위에 포함하지 않습니다.
- 현재 소스와 배포 버전의 설명을 구분하고 기존 릴리즈 노트에는 이후 구현 내용을 추가하지 않습니다.
- 설치·검사·배포 명령은 package script·실제 CI를 기준으로 안내합니다. native ABI 문제를 DB 초기화로 처리하지 않으며 데이터 보존·백업을 먼저 확인합니다.

### 뷰어 입력과 스크롤 조작

- 앱 화면 전환은 앱의 버튼·단축키로 수행하며 마우스 뒤로가기·앞으로가기 버튼의 기본 방문 기록 이동은 모든 화면에서 차단합니다. Backspace·Esc 뷰어 종료는 유지합니다.

- 확대/축소 컨텍스트 메뉴와 툴바 배율 버튼은 스크롤 보기에서만 표시합니다.
- 위로·아래로 스크롤 메뉴에는 기존 방향 아이콘을 사용하고 단축키 표시는 문자키·Space 뒤에 공백 한 칸과 방향키를 배치합니다.
- 스크롤 보기에서는 위 방향키·`zxcvbnm,./`를 위로 스크롤, 아래 방향키·`Space`를 아래로 스크롤에 배정하고 좌·우 방향키를 이전·다음 페이지 이동으로 구분합니다. 컨텍스트 메뉴도 위로 스크롤·아래로 스크롤·이전 페이지·다음 페이지 순으로 표시합니다. 다른 페이지 모드의 기존 이동 단축키는 유지합니다.
- 스크롤 보기 확대·축소는 상단 툴바, 페이지 모드 다음의 `확대/축소` 우클릭 하위 메뉴와 `+`/`-` 단축키에서 제공하며 모두 같은 항목별 배율을 조절합니다. 하위 메뉴는 확대·배율 초기화·축소 순이며 `0`은 100% 초기화입니다. 숫자 키패드도 지원하며 입력란·컨텍스트 메뉴 조작 중에는 뷰어 단축키를 적용하지 않습니다. Ctrl·Alt·Meta 조합은 배율 단축키에서 제외합니다. 툴바의 배율 표시는 클릭하면 100%로 초기화합니다.

### 테스트 보강과 구조 안정화

- 구조 안정화는 기존 동작을 유지하는 책임 분리에 한정합니다. `App`은 시작·프로필 gate와 라우팅을 연결하고, 각 화면의 조회·저장 상태와 확인 팝업은 전용 hook·컴포넌트에서 관리합니다. 신규 전역 상태 관리 라이브러리는 도입하지 않습니다.
- 프로필 선택·설정 화면은 공용 프로필 타입을 사용하고, 번역 함수 타입은 i18n 모듈에서 관리합니다. 라이브러리 알림은 기존 공용 Toast의 표시·종료 타이머를 재사용하며 화면별 위치·성공/오류 스타일을 유지합니다.

- 테스트 보강과 구조 안정화는 순차적으로 진행합니다. 테스트 단계에서는 재현된 오류에 필요한 수정만 포함하고, 컴포넌트·hook 분리는 다음 단계에서 검토합니다.
- HDT 미리보기는 준비한 프로필에서만 적용합니다. 다른 프로필의 미리보기 id는 폐기하고 저장하지 않습니다. 파일 추가 hook은 화면 이탈 후 남은 추가 요청·목록 갱신을 중단하며, HDT는 취소·화면 이탈 이전의 늦은 응답을 반영하지 않습니다.
- Modal은 열기 전 외부 포커스를 기억하고 닫을 때 스크롤을 바꾸지 않고 복원합니다. 자식의 자동 포커스나 처리 중 호출 버튼 비활성화가 복귀 대상을 바꾸지 않도록 유지합니다.
- 라이브러리의 저장된 스크롤 위치가 없으면 복원 대기를 생략해 최초 화면의 스크롤 기록을 놓치지 않습니다. 뷰어에서 돌아올 때는 저장된 위치를 복원합니다.

- 텍스트 입력은 저장 시 앞뒤 공백을 제거하며 내부 공백·줄바꿈은 유지합니다. 선택 입력의 공백-only 값은 `''`로 저장하고 필수 이름은 공백 제거 후 기존 유효성 검사로 거절합니다. 항목 추가에서 제목이 생략되면 자동 생성하지만 명시한 빈 제목은 대체하지 않습니다. 파일 선택으로 얻은 실제 파일명·경로는 이 입력 정리의 대상이 아닙니다.

- 뷰어 플레이리스트는 열람 전용으로 유지하며 순서 변경·항목 삭제·추가는 라이브러리에서만 수행합니다. 공용 패널의 `viewerMode`가 모든 편집 진입점을 차단하고, 목록에서 처리한 키 입력은 뷰어 단축키로 전파하지 않습니다.

- 신규 데이터 가져오기는 추가 직후 목록을 갱신하고 페이지 수·재생 시간 보완을 다시 실행합니다. 복수 파일/drop은 묶음 단위로 갱신하며 중복만 추가한 경우 생략합니다. 보완 완료 후 실제 변경이 있을 때 결과를 한 번 더 반영합니다. 기존 Queue 진행 중 추가된 데이터는 Queue 완료 후 재수집합니다.

- 라이브러리 grid의 빈 공간 왼쪽 클릭은 스크롤·선택을 변경하지 않습니다. 카드 클릭과 키보드로 목록에 진입하는 기존 동작은 유지합니다.

### 뷰어 복귀 시 라이브러리 보존

- 공통 라우트에서 라이브러리 화면을 보관해 목록·검색·페이지·선택·스크롤을 유지합니다. 뷰어는 별도 Suspense 경계에서 전환하며 숨긴 라이브러리는 조작·접근성과 팝업 단축키를 비활성화합니다.
- 일반 열람은 저장 응답의 목록 필드만 반영합니다. 읽기 상태 필터의 포함 여부가 바뀌거나 `updatedAt` 정렬이면 복귀 시 재조회하며, 항목 추가·상세 수정 종료·수동 새로고침 등 기존 명시적 갱신은 유지합니다. 플레이리스트는 복귀 시 최신 데이터로 동기화합니다.

### 썸네일 캐시 유지

- 썸네일 조회 결과와 진행 중 요청을 렌더러 세션에서 공유해 뷰어 복귀 시 전체 재조회를 막습니다. 일반 메타데이터·진행률 갱신은 썸네일을 무효화하지 않습니다.
- 썸네일 저장·항목 삭제/이동은 해당 id를 무효화하고, 프로필 전환·삭제는 전체를 초기화합니다. 초기화 이전 요청은 새 캐시에 반영하지 않습니다. 앱 재실행은 DB에서 다시 조회합니다.

### 복수 플레이리스트와 뷰어 목록 유지

- 목록은 프로필 단위로 생성·이름 변경·삭제합니다. 이름은 앞뒤 공백 제거 후 1~100자이며 같은 프로필 안의 중복 이름을 차단합니다. 기존 `Default`도 일반 목록으로 관리하되 마지막 하나의 삭제는 차단합니다.
- 라이브러리 패널 제목과 별도 건수 문구를 이름·건수 선택 필드로 대체합니다. 필드 아래 왼쪽에 생성·이름 변경·초기화, 오른쪽 끝에 표준 버튼 배경과 빨간 X 아이콘의 삭제 버튼을 배치합니다. 툴바와 같은 크기로 더하기·빈 실선 사각형+연필·빈 점선 사각형·X SVG를 사용하고 다국어 title·ARIA 이름을 유지합니다. 헤더 padding은 `10px 10px 10px 28px`이며 왼쪽 패널에서는 좌우를 반대로 적용합니다. 목록 선택은 공용 `Dropdown`의 키보드 조작과 태그 검색 필드의 이름·건수 배치를 따릅니다.
- 추가 버튼과 drop은 선택한 목록에 등록합니다. 카드 메뉴는 `리스트에 추가` 하나로 통합하고 하위 메뉴에 현재 프로필의 모든 목록을 표시합니다. 체크 아이콘은 파일이 등록된 모든 목록에 표시하고, 현재 선택 목록은 오른쪽의 `(현재)` 문구로 구분합니다. 목록이 하나여도 같은 메뉴 구조를 사용합니다. 메뉴를 다시 열 때 등록 여부를 갱신하며, 추가 대상 지정은 현재 선택을 변경하지 않습니다. 항목 추가로 패널을 자동으로 펼치지 않으며, 이미 펼쳐진 패널에서만 현재 플레이리스트에 포커스를 둡니다. 접힌 동안의 추가는 나중에 패널을 펼칠 때 포커스를 이동시키지 않습니다. 한 항목을 여러 목록에 등록할 수 있지만 같은 목록에는 한 번만 등록합니다.
- 선택은 프로필별 `playlist.activeId`로 복원하며 유효하지 않은 값은 해당 프로필의 가장 오래된 목록으로 대체합니다. 생성 후 새 목록을 선택하고 삭제 후에도 기존 선택이 유효하면 유지합니다.
- 뷰어에서는 목록을 전환하지 않습니다. 진입 시 목록 id를 고정하고 모든 파일 타입의 이동과 자동 이어보기에 전달합니다. 현재 파일이 목록에 없으면 이전·다음·자동 이동을 실행하지 않습니다.
- 목록 삭제·초기화는 등록 관계만 제거하며 라이브러리 항목과 파일을 유지합니다. 데이터 이관은 기존 `.db` 가져오기를 사용하고, 플레이리스트 복제·내보내기는 구현 범위와 후속 후보 모두에서 제외합니다.
- 이번 작업의 직접 검증·문서 반영은 기능 변경에 포함합니다. 전체 테스트·구조 안정화, 문서 안정화, Tauri 전환은 각각 별도 대화에서 진행합니다.

### 도서·만화 스크롤 보기와 항목별 표시 방식

- PDF·ZIP의 표시 방식은 `items.bookViewMode`의 `single`/`scroll`/`double-ltr`/`double-rtl`로 관리합니다. 기존 항목은 null을 유지하고 한 페이지로 fallback합니다. 과거 프로필 설정을 항목에 일괄 이관하지 않습니다.
- 스크롤 모드에서 위·아래 화살표는 창 높이의 50%만큼 부드럽게 이동하고 좌·우 화살표는 페이지를 이동합니다. `1` 키는 한 페이지와 스크롤을 전환하고 두 페이지 상태에서는 한 페이지로 돌아갑니다. `2` 키는 한 페이지·스크롤에서 좌→우 두 페이지로 전환한 뒤 좌→우/우→좌를 토글합니다.
- 기본 폭은 컨테이너와 1000px 중 작은 폭이며 스크롤 전용 50~300% 배율을 곱합니다. 축소·초기화·확대 버튼은 스크롤 모드에서만 표시하고 25% 단위로 조절합니다. 다른 보기 모드의 크기는 변경하지 않습니다.
- 페이지는 실제 이미지 비율로 계산한 높이로 간격 없이 배치합니다. 현재 읽는 화면과 주변 화면만 요소로 표시하고 다른 구간은 전체 높이 안의 위치 정보로 유지합니다. 페이지 전환만으로 스크롤 위치를 다시 대입하지 않습니다. 방향키 애니메이션은 240ms이며, 높이 변경 중에도 상대 이동을 이어갑니다.
- 화면 위쪽 페이지 번호와 페이지 전체 높이 대비 위쪽 위치 비율을 함께 저장합니다. `bookScrollZoom`은 0.5~3, `bookScrollOffset`은 0~1의 nullable real 컬럼입니다. 기존 값이 없으면 100%·페이지 시작을 사용합니다. 픽셀 값 대신 비율을 사용해 배율·창 크기 변경 후에도 같은 내용으로 복원합니다.
- 위치는 180ms debounce로 저장하고 뷰어 종료·항목 전환·모드 변경·beforeunload에서 대기 저장을 반영합니다. 복원에 필요한 실제 페이지 크기가 확인되기 전에는 임시 로딩 화면 위치로 저장값을 덮지 않습니다. 이동·복사·과거 DB 가져오기에서도 유효한 배율과 위치 비율을 보존합니다.
- ZIP 스크롤은 실제로 화면에 걸친 페이지 수를 기준으로 캐시 범위를 늘리며 최소 2페이지와 기존 128MiB 추정 예산을 적용합니다. 현재 화면 이미지의 표시를 우선하는 정책은 같습니다. PDF는 범위 밖 렌더 작업을 취소하고 문서를 파기하며 큰 canvas는 렌더 버퍼를 16M pixel과 한 변 32767px 이하로 조절합니다.

### ZIP 페이지 이동 성능과 이미지 보관

- 순서 6은 기존 한 페이지·두 페이지 보기의 성능 개선에 한정합니다. 스크롤 보기와 항목별 표시 방식 저장은 후속 순서 7에서 완료했습니다.
- Electron sender별 ZIP 세션을 한 개 유지하고 비동기 파일 읽기와 JSZip 열기를 한 번만 수행합니다. 파일 전환·뷰어 종료·창 종료·renderer crash·전체 페이지 reload 시 해제합니다. 파일을 외부에서 수정하면 뷰어를 다시 열어 새 내용을 읽습니다.
- 이미지 IPC는 base64 대신 바이너리와 실제 MIME type을 전달합니다. renderer는 Blob URL과 이미지 decode를 사용하고 창 범위에서 벗어난 URL을 해제합니다.
- 주변 범위는 현재 화면과 다음·이전 각 한 화면입니다. 한 페이지 보기에서는 최대 3페이지, 두 페이지 보기에서는 최대 6페이지이며 파일 양 끝에서는 줄어듭니다. 현재 화면, 다음 화면, 이전 화면 순으로 한 번에 한 페이지를 읽습니다. 빠른 이동 중 범위를 벗어난 결과는 폐기하고 최신 화면을 우선합니다.
- 이미지 보관 예산은 128MiB이며 이미지 파일 바이트와 `width × height × 4`의 정적 RGBA 추정치를 합산합니다. 범위 밖 페이지를 제거하고 예산 초과 시 주변 이미지를 제거합니다. 현재 화면 자체가 예산을 초과하면 표시를 우선하고 추가 미리 읽기를 중단합니다. 이는 앱 전체 메모리의 상한이 아니며 ZIP 원본, IPC 복사, 로딩 중 이미지와 브라우저 내부 메모리는 별도입니다.
- 디스크 캐시는 도입하지 않습니다. 벤치마크용 합성 ZIP은 측정 fixture이며 실제 뷰어 캐시와 구분합니다.

### 창 상태 복원과 뷰어 조작

- 창 상태는 DB 준비 전에도 복원할 수 있도록 프로필 설정 대신 포터블 userData의 `window-state.json`에 저장합니다. 일반 창의 좌표·크기와 모니터 id·작업 영역, 최대화 여부를 유지하고 전체화면·최소화는 복원하지 않습니다.
- 저장한 모니터가 없으면 기본 모니터로 fallback하며, 화면 작업 영역이 바뀌면 전체 창이 보이도록 위치·크기를 제한합니다. 변경 시 250ms debounce로 저장하고 닫을 때 즉시 저장합니다.
- 모든 뷰어는 마우스가 창 안에 있어도 2.4초간 표시를 유지하는 조작이 없으면 툴바와 커서를 함께 숨깁니다. 마우스 조작과 창 포커스 복귀로 다시 표시하며, 열린 컨텍스트 메뉴는 숨김을 보류합니다. PDF·ZIP(CBZ)은 읽기를 방해하지 않도록 키보드 표시를 Tab·Shift+Tab·컨텍스트 메뉴 키·Shift+F10으로 제한하고 페이지 이동·스크롤·확대 키는 숨김 타이머를 갱신하지 않습니다. 동영상은 모든 키 입력으로 표시하며 일시정지와 반복 재생도 동일하게 처리합니다.
- seek bar는 배경 위 hover 구간, 그 위 현재 재생 구간을 표시합니다. 현재 진행률을 hover 위치로 대체하지 않습니다. 조작 영역은 높이 16px로 유지하고, 내부 막대는 기본 6px에서 마우스 호버 시 160ms transition으로 12px까지 확장합니다. 두 구간이 겹치는 부분에는 흰색 30% 투명도 레이어를 추가해 현재 재생 시점 이전의 hover도 밝기 차이로 구분합니다. hover 시각 표시는 양 끝에서 안쪽으로 정렬합니다. 볼륨 조절 바는 native range 입력을 투명한 조작 레이어로 유지하고, 별도 트랙과 thumb를 그려 트랙만 기본 4px에서 호버 시 12px로 160ms transition합니다. thumb 위치는 세로 중앙에 고정합니다. 키보드 포커스는 두께 확장 조건에 포함하지 않습니다.

### 프로필 단위 태그명 변경·병합

- 설정의 데이터 관리 탭 첫 항목에서 현재 프로필의 태그만 관리합니다.
- 이름 중복 시 더 작은 내부 id를 유지하고, 연결 항목의 합집합을 중복 없이 보존한 뒤 삭제할 태그를 제거합니다. 유지할 태그가 변경 전 이름을 가진 경우 최종 이름도 변경합니다.
- 병합 대상과 유지할 id를 실행 전에 표시하고 버튼을 `태그 병합`으로 변경합니다.
- 변경 전·후는 폴더 경로 일괄 변경과 같은 간격의 연속 입력으로 배치하고 레이블 대신 placeholder를 표시합니다. 공용 태그 검색 요소를 사용해 변경 전은 기존 태그 선택, 변경 후는 기존 태그 검색 또는 새 이름 입력을 지원합니다.
- 공용 태그 검색 요소의 id 표시는 선택 옵션이며, 설정의 태그 변경·병합에서만 활성화합니다.
- 태그명 변경·병합은 후보 선택 직후 이름을 유지하고 목록만 닫습니다. 입력 재클릭·수정·방향키로 다시 열고, 입력 그룹 밖으로 blur 시 닫습니다. 입력 내부 우측의 빨간 원형 X 버튼으로 값을 비울 수 있으며, 비운 뒤 입력 포커스를 유지하고 실행 버튼을 비활성화합니다.
- 공용 검색 후보는 기본 최대 20건이며 호출부에서 출력 건수와 데이터 수 정렬 방향을 지정합니다. 태그 변경·병합은 50건, 변경 전 오름차순·변경 후 내림차순을 사용합니다. 변경 후 입력을 먼저 허용하되 실행은 두 값이 모두 유효할 때 허용합니다.
- 선택 중인 검색 조건은 삭제된 id를 유지할 id로 치환하고 중복 선택을 제거합니다. 단순 이름 변경은 기존 id를 유지합니다.
- IPC는 active profile과 요청 당시 profile id를 함께 확인하고, SQLite transaction으로 전체 변경의 원자성을 보장합니다.

### 공용 툴팁 위치와 컨테이너 경계

- 위치 계산과 크기 감지는 표시 상태와 분리합니다. 생성 직후 계산하고, 숨김 상태에서도 재계산하며 닫을 때 위치를 초기화하지 않습니다.
- 툴팁은 트리거 아래 왼쪽 정렬, 기본 폭 240px을 사용하고 오른쪽 넘침 시 컨테이너 오른쪽 끝에 맞춥니다.
- 가장 가까운 `.tooltip-container`를 기준으로 `content-box`·`padding-box`·`border-box` 경계를 선택합니다. 언어 안내는 메타데이터 전체에 `content-box`를 적용합니다.
- 이후 툴팁 구현은 공용 `Tooltip`과 [툴팁 기준](tooltip-guidelines.md)을 따릅니다.

### 선택 태그 검색과 언어 없음

- 태그 조건은 선택 목록, 검색 입력/선택 버튼, 등록 목록 순서로 표시합니다. 선택 목록은 고정 높이의 한 줄 가로 스크롤이며 스크롤바를 항상 표시합니다.
- 등록 태그는 전체 목록을 표시하고 최대 180px 높이의 목록 내부에만 세로 스크롤을 적용합니다. 더보기/접기는 제거하며, 태그 제목·선택 목록·검색 입력은 등록 목록과 함께 스크롤하지 않습니다. 미지정 조건은 유지합니다.
- 검색 조건 팝업은 내용에 맞게 높이를 정하고 화면 높이를 넘지 않도록 제한합니다.
- 검색 후보는 현재 프로필에서 실제 사용 중인 미선택 태그입니다. 검색으로 태그를 새로 생성하지 않고, 선택은 기존 AND 조건에 추가합니다.
- 콘텐츠 언어 `미지정`은 기본값 `unspecified`, `없음`은 대사 등이 없는 콘텐츠를 나타내는 별도 값 `none`으로 저장합니다. 기존 빈 언어값은 `unspecified`로 변환합니다.
- 미지정 언어 배지는 카드에 표시하지 않고, `없음`은 카드에 `N/A`로 표시합니다. 한 번 지정된 언어는 `미지정`으로 되돌릴 수 없으며 상세정보 UI와 IPC에서 제한합니다.
- 언어 되돌림 제한 안내는 수정 모드의 언어 레이블 옆 원형 물음표 툴팁으로 제공하고, 입력란 아래의 별도 공간은 차지하지 않습니다. 호버와 키보드 포커스로 표시합니다.
- 검색의 전체 언어는 조건을 생략하고, `unspecified`와 `none`은 각 저장값을 직접 조회합니다. 언어 `기타`의 저장값 `other`는 유지합니다.

### 콘텐츠 분류와 파일 타입 분리 및 팝업 배경 클릭 기준

- PDF는 공고문 등 일반 문서, ZIP은 사진 모음 등 일반 이미지 압축파일을 포함하는 표현으로 표시합니다.

- 검색, 목록 배지와 플레이리스트 설명은 콘텐츠 분류를 표시합니다. 상세정보에서는 콘텐츠 분류를 수정할 수 있고 파일 타입은 읽기 전용으로 표시합니다.
- 뷰어, 진행률 단위와 플레이리스트 등록 가능 여부는 파일 타입을 기준으로 판단합니다. 콘텐츠 분류를 바꿔도 PDF/ZIP/동영상 뷰어 연결은 유지합니다.
- 이 기준은 이전 플레이리스트 정책의 `book`/`comic`/`video` 콘텐츠 타입 제한을 대체합니다. `기타`로 분류한 지원 파일도 플레이리스트에 등록할 수 있습니다.
- 신규 PDF/ZIP(CBZ 포함)은 도서, 동영상 파일은 동영상으로 기본 분류합니다. HDT 가져오기도 같은 기본값을 적용합니다.
- 기존 데이터와 과거 DB 가져오기는 저장된 콘텐츠 분류를 유지합니다. 파일 재연결 시에는 파일 타입만 새 확장자로 산정합니다.
- 공용 Modal은 누름과 놓음이 모두 배경인 클릭에서만 최상단 팝업을 닫습니다. 팝업 내부와 배경 사이의 drag는 닫힘으로 처리하지 않습니다.

- 루트 `README.md`는 저장소 입구 역할만 담당하고, 상세 문서는 `docs/`로 연결합니다.

### 문서 구조는 축약형으로 유지

- 참조한 `whismi-docs`의 운영 패턴 중 현재 프로젝트에 필요한 최소 세트만 가져옵니다.
- 핵심 문서는 `current-status`, `next-task`, `roadmap`, `decisions`, `changelog`입니다.
- 이 프로젝트 특성을 반영해 `architecture`, `setup`, `release-ci`, `backlog`를 추가합니다.

### 기존 루트 문서는 `docs/`로 흡수

- 기존 `README.CI.md` 내용은 `docs/release-ci.md`로 통합합니다.
- 기존 `TODO.md` 내용은 `docs/backlog.md`와 `docs/next-task.md`로 재구성합니다.
- 루트에는 상세 운영 문서를 계속 늘리지 않습니다.

### `AI_WORKFLOW.md` 도입

- 참조 문서 프로젝트의 `AI_WORKFLOW.md` 운영 방식 중 현재 저장소에 맞는 규칙만 축약 반영합니다.
- `develop` 고정 같은 저장소별 정책은 그대로 복제하지 않고, 현재 브랜치와 작업 트리 확인 규칙으로 조정합니다.
- 미래 세션은 `docs/AI_WORKFLOW.md`를 기준으로 문서 갱신 여부를 판단합니다.

### 문서 작성 규칙과 commit message 규칙 반영

- 참조 문서 프로젝트의 `doc-style-guide.md` 운영 방식을 이 저장소에도 적용합니다.
- 문서는 한글 중심으로 짧고 직접적으로 작성하되, 기술 용어와 코드 연결 이름은 영문 표기를 유지합니다.
- commit message는 `접두사: 제목` 형식을 기본으로 사용합니다.
- commit/push 실행 승인 규칙은 `AI_WORKFLOW.md`와 `doc-style-guide.md`에 함께 반영합니다.
